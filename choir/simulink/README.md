# choir_sim: Simulink model of the Choir receiver

- **What it is.** This model runs the same MATLAB code as `run_all.m` (`src/channel_slot` and `src/rx_step`). It does one frame period (28.4 ms) per simulation step. It is not a separate implementation.
- **How to run.** In MATLAB, go to this folder and run `build_choir_sim`, which writes `choir_sim.slx`. Then run `run_choir_sim`.
  - It runs the simulation and saves the two PNG files.
  - It also runs the plain MATLAB loop again and prints both results.
- **Blocks.**
  - `ChoirStep.m` contains the receiver as a System object.
  - `choir_step_sfun.m` is a Level-2 MATLAB S-Function block that steps it once per frame. The MATLAB System block needs a Java runtime, which is not installed on this MATLAB.
  - Execution is interpreted, with no code generation.
- **Scope "Receiver"** shows only receiver outputs:
  - verified frame in this step (0/1)
  - state (1 SEARCH, 2 ALIGN, 3 DECODE, 4 FALLBACK)
  - number of dishes in use
- **Scope "Scorer (truth)"** shows the cumulative number of frames with telemetry identical to the transmitted telemetry, the same test as in `score_run`. The receiver does not get this value.
- **Scenario.** Seed 301, 300 frames, 2 dB, `random_faults(301, 300, 8)`. The default values are in `ChoirStep.m`.
- **Result (checked).**
  - In Simulink, 275 of 300 frames were correct (91.7%). This is the same as the plain MATLAB loop and `results/faults_raw.mat` for seed 301.
  - The receiver state was the same at all 301 steps.
- **Images.**
  - `choir_sim_outputs.png` shows the four logged signals over time.
  - `choir_sim_diagram.png` shows the block diagram.
